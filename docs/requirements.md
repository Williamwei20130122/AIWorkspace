# 需求说明 · AIWorkspace 教学系统

- 版本：v0.1（项目基底 / 最小可用版本）
- 更新：2026-11
- 状态：已实现并可在本地与 Docker 中运行

## 1. 背景与目标

学校需要一个**不依赖第三方平台**、可在校内网络部署的网页教学系统，让教师完成「建班 — 建课 — 布置作业 — 批改反馈」的闭环，学生完成「入班 — 查看作业 — 提交 — 查看成绩」的闭环。

目标：

1. 一个可运行的工程底座：登录、角色区分、数据模型、页面框架、Docker 部署全部就绪。
2. 教师/学生两端核心流程可用，能支撑课堂演示与真实小规模使用。
3. 后续功能（附件、通知、统计、管理员）可以直接在此底座上迭代，不需要推倒重来。

## 2. 用户与场景

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| 教师 | 学校任课教师 | 快速建班、发布作业、批改省时、掌握提交进度 |
| 学生 | 班级学生 | 知道今天要交什么、能提交、能看到分数和评语 |
| 管理员 | 预留角色 | 后续做账号与学校级管理（本期不含页面） |

典型场景：

- 教师创建「初二（3）班」，把 6 位邀请码发到班级群；学生登录后输入邀请码入班。
- 教师在班级下建「数学」课程，发布作业并设置 3 天后截止。
- 学生提交作业；教师在工作台看到待批改数量，进入作业详情逐份打分。
- 学生打开作业详情看到分数与评语。

## 3. 功能需求

### 3.1 账号与会话（P0，已实现）

- FR-1 邮箱 + 密码登录；演示账号由种子数据创建。
- FR-2 会话使用 HttpOnly + SameSite=Lax Cookie，HMAC 签名，7 天有效。
- FR-3 未登录访问受保护页面跳转 `/login`；角色不符跳转到自己角色的首页。
- FR-4 退出登录清除会话。

### 3.2 教师端（P0，已实现）

- FR-5 工作台：班级数、学生数、课程数、待批改数；最近提交；即将截止作业。
- FR-6 创建班级（名称、年级可选），系统生成唯一 6 位邀请码。
- FR-7 班级详情：邀请码展示、学生名单、课程列表、每门课最近作业、公告列表。
- FR-8 在班级下创建课程（名称、简介）。
- FR-9 发布作业：标题、要求、分值、截止时间（可空）。
- FR-10 作业列表：按创建时间倒序，展示课程/班级、截止、提交数、已批改数、分值。
- FR-11 作业详情：已提交列表（学生、时间、内容、分数、评语、批改入口）；未提交学生名单。
- FR-12 批改：分数 + 评语，可反复修改；保存后学生端立即可见。
- FR-13 发布班级公告。

### 3.3 学生端（P0，已实现）

- FR-14 工作台：班级数、待交作业数、已提交数、平均分（按得分率）；即将截止作业；最近公告。
- FR-15 邀请码加入班级（重复加入幂等）。
- FR-16 我的班级：班级、教师、人数、课程与作业数。
- FR-17 我的作业：全部作业与状态（未提交 / 已提交 / 已批改 + 分数）。
- FR-18 作业详情：要求、分值、截止时间；提交 / 重新提交（重交会清空原分数，需教师重新批改）。
- FR-19 成绩单：平均分、按课程分组的成绩列表与百分比。

### 3.4 系统能力（P0，已实现）

- FR-20 健康检查 `GET /api/health`（数据库连通即 200）。
- FR-21 数据库迁移与演示数据可重复初始化。
- FR-22 Docker 单容器部署，宿主 3100 端口，SQLite 数据卷持久化。

### 3.5 本期明确不做（P1/P2）

- 附件上传与在线预览（预留 `Submission.attachmentUrl` 字段）
- 通知中心 / 邮件提醒
- 管理员后台、多学校隔离
- 成绩图表、导出 Excel/PDF
- 第三方登录（微信/钉钉/SSO）
- 移动端 App / 小程序

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 部署 | 一条 `docker compose up -d --build` 启动；无外部数据库依赖 |
| 端口 | 宿主机 `3100`；容器内同样监听 3100，可用 `PORT` 覆盖 |
| 数据 | SQLite 文件在命名卷 `/data/app.db`，重启不丢；`down -v` 可重置 |
| 安全 | 口令 scrypt 加盐哈希；会话 HMAC 签名；HttpOnly Cookie；所有查询按登录用户过滤 |
| 性能 | 单机 300 人规模内页面首屏 < 2s（内网）；列表页不分页（数据量小） |
| 兼容 | Chrome / Edge / Safari 最近两个大版本；桌面优先，移动端可用 |
| 可维护 | TypeScript strict；接口契约文档化；数据模型变更必须带 migration |
| 可观测 | `/api/health`；容器健康检查；结构化错误日志到 stdout |

## 5. 验收标准

- [ ] `npm run build` 无类型错误，构建通过
- [ ] 本地 `npm run dev` 后 `http://localhost:3100` 可登录
- [ ] 教师可建班 → 建课 → 发作业 → 批改；学生可入班 → 提交 → 看到分数
- [ ] 教师看不到其他教师的班级；学生看不到未加入班级的数据
- [ ] 刷新页面会话保持；退出后再访问受保护页跳登录
- [ ] `docker compose up -d --build` 后 `http://localhost:3100/api/health` 返回 `{"ok":true}`
- [ ] 容器重启后数据仍在（卷持久化）
- [ ] 页面在 375px 宽度下无横向滚动、主要操作可完成
